# CORTEX 테스트 시나리오 (Phase 1~6)

> 접속: 로컬 `http://localhost:7777` / 외부·모바일 `https://cortex.revuplan.com`
> 문제 발견 시: 어느 시나리오 몇 번에서 뭐가 났는지만 알려주면 됨.

---

## A. 에이전트 상태 (Phase 1)

**A1. 상태 dot 실시간 표시**
1. 아무 프로젝트나 터미널에서 직접 `claude` 실행 (CORTEX 밖에서도 됨)
2. 프롬프트 입력 → CORTEX 사이드바 "에이전트" 섹션에 해당 프로젝트가 **🟣 작업 중**으로 뜨는지 (5초 내)
3. Claude가 권한을 물어보면 → **🟡 권한 대기**로 바뀌는지
4. 턴이 끝나면 → **🟢 완료** + 이름이 굵게(unread) 되는지

**A2. unread 확인 처리**
1. 완료(🟢 굵게) 상태의 에이전트를 사이드바에서 클릭
2. → 워크스페이스로 이동하고, 굵기가 풀리는지(읽음 처리)

**A3. 세션 종료 정리**
1. Claude 세션을 `/exit` 등으로 종료
2. → 사이드바 에이전트 목록에서 사라지는지

---

## B. 터미널 생존성 (Phase 2)

**B1. 페이지 이탈 후 복귀**
1. 워크스페이스에서 프로젝트 열고 🤖 Claude 모드로 뭔가 작업 시킴
2. 대시보드로 이동했다가 다시 워크스페이스로 복귀
3. → 터미널이 **끊기지 않고 그동안의 출력까지 복원**되는지

**B2. 새로고침 생존**
1. Claude 작업 중에 브라우저 **새로고침(F5)**
2. 같은 프로젝트를 다시 열면 → 기존 세션에 재부착되고 스크롤백이 살아있는지
   (탭 목록 자체는 초기화되는 게 정상 — 세션은 서버에 살아있음)

**B3. 모바일 백그라운드 복귀**
1. 폰에서 cortex.revuplan.com 열고 Claude 실행
2. 다른 앱 갔다가 1~2분 후 복귀
3. → 자동 재접속되고 놓친 출력이 replay되는지

**B4. 명시적 종료**
1. 터미널 우상단 "종료" 클릭 → 세션 죽는지
2. 탭의 ✕로 탭 닫기 → 다시 열면 **새 세션**으로 시작하는지 (좀비 없음)

---

## C. 사용량 추적 (Phase 3)

**C1. 대시보드 사용량 패널**
1. 대시보드의 "Claude 사용량" 카드 확인
2. → 총비용(추정)/출력토큰/캐시읽기/턴수 + 일별 막대 + 모델별/프로젝트별 TOP 표시되는지
3. 7일 ↔ 30일 토글 동작하는지

**C2. 최신 반영**
1. Claude로 아무 작업 하나 실행
2. 사용량 카드의 ⟳(다시 스캔) 클릭
3. → 오늘 막대/턴 수가 증가하는지

---

## D. 알림 (Phase 4)

**D1. 완료 알림**
1. 사이드바 벨 클릭 → "브라우저 알림 켜기" 눌러 권한 허용
2. 아무 프로젝트에서 Claude에게 작업 시키고 완료될 때까지 대기
3. → 벨에 빨간 뱃지 + 드롭다운에 "✅ ○○ 작업 완료" + **브라우저 알림 팝업**까지 오는지

**D2. 권한 대기 알림**
1. Claude가 권한 물어보는 상황 만들기 (위험한 명령 요청)
2. → "🔐 ○○ 권한 대기 중" 알림 오는지

**D3. 알림 클릭 이동**
1. 알림 드롭다운에서 항목 클릭
2. → 해당 프로젝트 워크스페이스로 이동하는지

**D4. 모바일 알림**
1. 폰(외부 도메인)에서 벨 권한 허용 후 D1 반복
2. → 폰 브라우저에서도 알림 오는지 (단, 브라우저가 완전히 닫혀 있으면 안 옴 — 정상. 진짜 백그라운드 푸시는 다음 단계)

---

## E. 병렬 워크트리 (Phase 5)

**E1. 단일 워크트리**
1. git 프로젝트 상세 → "병렬 워크트리" 카드
2. 브랜치명 `test-a`, ×1, 프롬프트 없이 "생성 + Claude 열기"
3. → 워크스페이스에 `프로젝트명 · test-a` 탭이 열리고 Claude가 그 워크트리 경로에서 실행되는지
4. 터미널에서 `pwd` → `~/.cortex-worktrees/...` 경로인지, `git branch` → `test-a`인지

**E2. fan-out (핵심 기능)**
1. 브랜치명 `try-fix`, **×2**, 시작 프롬프트에 "이 프로젝트 구조를 한 문단으로 요약해줘" 입력 후 생성
2. → 탭 2개(`try-fix-1`, `try-fix-2`)가 열리고 **양쪽 Claude가 같은 프롬프트로 동시에 작업**하는지

**E3. 안전 삭제**
1. 워크트리 하나에서 파일을 수정해 dirty로 만들기
2. 카드에서 ✕ 삭제 → "미커밋 변경 N건" 거부 메시지 + 강제 삭제 confirm 뜨는지
3. clean 워크트리 삭제 → 조용히 삭제되는지
4. 워크트리에 커밋을 만들고(머지 안 함) 삭제 → "브랜치 '○○'는 보존됨" 안내가 나오고 `git branch`에 남아있는지

---

## F. 리뷰 + AI 커밋 (Phase 6a)

**F1. 소스 컨트롤 패널**
1. 변경사항 있는 프로젝트를 워크스페이스에서 열고 **📝 리뷰** 모드 클릭
2. → 브랜치명 + 변경 파일 목록(M/A/??/D 색상) 표시되는지
3. 파일 클릭 → diff가 +초록/-빨강으로 렌더링되는지 (새 파일은 전체 + 표시)

**F2. diff 코멘트 → Claude 전송 (orca 핵심 기능)**
1. 같은 탭을 먼저 🤖 Claude 모드로 한 번 실행해 세션을 만들어 둠 → 📝 리뷰로 전환
2. diff 라인 클릭 → "AI에게 메모" 입력 (예: "이 부분 함수로 분리해줘") → 저장. 2~3개 등록
3. 하단 "📝 코멘트 N개 Claude로 보내기" 클릭
4. → 🤖 Claude 모드로 돌아가면 **코멘트들이 프롬프트로 입력되어 Claude가 작업 시작**했는지

**F3. AI 커밋 메시지**
1. 리뷰 모드 하단 "🤖 AI 메시지" 클릭 (수십 초 소요)
2. → 커밋 메시지가 diff 내용에 맞게 채워지는지
3. "커밋" 클릭 → 커밋되고 파일 목록이 비워지는지 ("커밋+푸시"는 원격 있는 프로젝트에서)

---

## G. 자동화 (Phase 6b)

**G1. 즉시 실행**
1. 프로젝트 상세 → "자동화" 카드 → + 클릭
2. 프롬프트: "이 프로젝트의 최근 커밋 3개를 한 줄씩 요약해줘", 매일 09:00으로 추가
3. "▶ 지금" 클릭 → 수십 초 후 알림 "🤖 [자동화] ○○ 실행 완료" 오는지
4. "결과" 버튼 → Claude의 실제 출력이 보이는지

**G2. 예약 실행**
1. 자동화의 시간을 **현재 시각 +2분**으로 새로 등록
2. 2~3분 대기 → 자동으로 실행되고 완료 알림 오는지 (60초 tick이라 최대 1분 오차)

**G3. 토글/삭제**
1. 토글 off → 예약 시간이 지나도 실행 안 되는지
2. ✕ 삭제 → 목록에서 사라지는지

## 알려진 한계 (버그 아님)
- **서버 재시작**(재빌드/launchctl kickstart) 시 터미널 세션은 소멸 → 재접속하면 "새로 시작합니다" 안내 후 새 세션 (orca는 별도 데몬으로 해결 — 필요해지면 다음 단계)
- 브라우저 알림은 **브라우저가 떠 있어야** 수신 (백그라운드 Web Push는 미구현)
- 워크트리 안에서 도는 에이전트는 사이드바에서 프로젝트명 대신 브랜치 폴더명으로 표시됨
- 사용량 비용은 **추정치** (fable 단가 미공개 → opus 단가 적용)
- 이미 떠 있던 Claude 세션은 훅 미적용 — 새로 시작한 세션부터 상태 추적됨
